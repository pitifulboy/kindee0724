# 新味智枢（electron-office）代码评审报告

> 评审日期：2026-10-05 ｜ 版本：v3.6.1 ｜ 分支：XWZS_1004
> 评审方式：三人专家团并行 **只读** 审查 —— ① 主进程/后端 ② 渲染层/前端 ③ 工程化/构建发布。
> 范围：全量通读 `src-electron/`（7443 行）+ 全部配置（vite/tsconfig/electron-builder/tailwind）+ 脚本 + docs。
> **本次评审未修改任何代码。** 项目当前可正常运行，本报告只给出「可优化点」。

---

## 0. 总体结论

- **架构分层是清晰的**：渲染层（React）/ 预加载桥（contextBridge）/ 主进程 IPC / 业务模块（excelMerge、kingdeeImport）四层分明；离线不联网、`contextIsolation:true` / `nodeIntegration:false` / `webSecurity:true`、preload 不暴露原始 `ipcRenderer`，安全基线到位；退出与项目存储（双路径 + mtime 择新 + 重试）设计细致。
- **主要问题不是「写错」，而是「写重、写旧、写肿」**：
  1. **重复实现多**：Excel 读取/清洗/写盘助手、预设管理器、类型定义、原生拖拽、id 生成、步骤执行编排均有多份近似副本。
  2. **死代码/注释块多**：旧预设管理 IPC、旧一键生成入口、被注释的 RECOMMENDED_CONFIG 与隐藏 UI，合计可净减 **约 500~600 行**。
  3. **巨型组件**：`CombinedPage.tsx` 2034 行 / 44 个 `useState`、无 `memo`，任一输入整页重渲。
  4. **工程护栏缺失**：无 `typecheck`（且 `tsc` 从未被执行）、无 lint、无测试、无 CI；发布脚本存在**中文源码编码风险**。
- **另有 2 个用户可见的真实缺陷**（非逻辑设计问题，属遗漏）：Sidebar 日期白底白字、辅助表拖拽监听器泄漏。

严重度口径：**P0** = 会导致错误/数据风险/用户可见异常；**P1** = 明显应改；**P2** = 优化建议。

## 1. P0 —— 建议优先处理

### P0-1　发布脚本可能把中文源码写成 ANSI/GBK（静默乱码）
- **证据**：`build-release.ps1:35` `$pkg | ConvertTo-Json -Depth 10 | Set-Content "package.json"`；`build-release.ps1:42` `Set-Content $appTextPath $content` —— 均**未指定 `-Encoding`**。Windows PowerShell 5.1 的 `Set-Content` 默认是系统 ANSI（简中为 GBK/936）。
- **影响**：`npm run release` 后 `appText.ts`（含全部中文 UI 文案）可能被写成 GBK，Vite/esbuild 按 UTF-8 读取 → **界面中文整体乱码**；`package.json` 中含非 ASCII 的 description 会被替换为 `?`。当前工作树恰好是 UTF-8，属「这次没事、下次踩雷」。
- **建议**：改用显式 UTF-8 写入（`[System.IO.File]::WriteAllText($p,$s,[System.Text.UTF8Encoding]::new($false))`）；更稳妥是**不要用脚本改写源码文本**，改为构建期注入版本常量（见 P0-2）。

### P0-2　界面版本号与安装包版本号「双源」且不同步
- **证据**：安装包版本取 `package.json:3`（`3.6.1`）；界面版本取 `src-electron/renderer/config/appText.ts:12`（`version: 'v3.6.1'`），由 `Sidebar.tsx:256` 显示。同步仅靠 `build-release.ps1:41` 的正则 `"version: 'v[\d.]+'"` —— 而 `package.json:11` 的 `npm run build` **完全不跑该脚本**。
- **影响**：直接 `npm run build` 出包时，界面显示旧版本、安装包是新版本；正则对格式敏感，失配即静默错版。
- **建议**：消除双源 —— Vite `define` 注入 `__APP_VERSION__`（来自 `package.json.version`），`appText.version` 由该常量派生。

### P0-3　Sidebar 非选中项目的「日期」白底白字，完全不可见
- **证据**：`src-electron/renderer/components/Sidebar.tsx:208`
  ```tsx
  {lastModified && (<p className="text-[10px] text-white">{lastModified}</p>)}
  ```
  同区块的项目名（`:204`）与图标（`:198`）都做了 `isActive ? text-white : text-black` 判断，**唯独日期漏判**；非选中项背景为白/灰。
- **影响**：所有非选中项目的修改日期在白色面板上不可见，用户无法从列表判断新旧。
- **建议**：与项目名一致，改为条件色。

### P0-4　辅助表拖拽区监听器持续叠加（监听器泄漏）
- **证据**：`CombinedPage.tsx:266-292` 的 `setupAuxDrop()` 内部 `addEventListener(...)` 并 `return` 一个 cleanup 函数；但调用点 `CombinedPage.tsx:1386` `onMouseEnter={() => setupAuxDrop(aux.id)}` **丢弃了返回值**，cleanup 永不执行。
- **影响**：鼠标每次划过该区域就新增一组 `dragover/dragleave/drop` 监听；一次 drop 会触发 N 次 `listExcelFiles` / `getColumns` 读盘，表现为重复读取、状态抖动，组件卸载也不回收。
- **建议**：改为 `useEffect` 统一绑定/解绑（依赖 `auxTables`），或抽 `useNativeDropZone` Hook。

### P0-5　`.xls` 可被选中，但 exceljs 读不了
- **证据**：过滤/后缀白名单含 `.xls`：`src-electron/main/ipc/index.ts:61`、`:64`；`CombinedPage.tsx:424`、`:455`、`:630`。而实际读取全走 `workbook.xlsx.readFile(...)`：`excelMerge/service.ts:42`、`kingdeeImport/service.ts:107/152/200/218`。
- **影响**：用户选中 BIFF 格式 `.xls` 时必抛错，报错信息与操作预期不符（"能选但必失败"）。
- **建议**：白名单收窄为仅 `.xlsx`，或在读取前给出「请另存为 .xlsx」的友好提示。

### P0-6　图标源文件未入库，全新环境 `npm run build` 会失败
- **证据**：`.gitignore:12` 忽略 `icons/myicons.jpg`；`git ls-files icons/` 为空；但 `scripts/generate-icon.js:46` 以它作为输入，且 `package.json:11` 的 build 首步就是 `npm run generate-icon`。
- **影响**：本机因有该 jpg 才能构建；**其他环境（同事/新克隆/打包机）构建即 ENOENT 失败** → 发布不可复现。
- **建议**：把图标源纳入版本库（或改放 `build/` 并提交），或让脚本在输入缺失时沿用已提交的 `icon.ico`。
