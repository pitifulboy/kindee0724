## 2. 整改前后对照（四类）

| 类别 | 整改前 | 整改后 |
| --- | --- | --- |
| **配色** | primary-600 为青色、primary-700 为蓝色，是两条色阶拼接；成功态误用蓝色 | 主色统一为单调蓝色系（50 最浅 → 900 最深）；新增 `success` 语义色；成功态一律用绿 |
| **文案** | 「左连接」「内连接」「右连接」「模板表」等术语面向研发 | 全部中文化：「全部订单都保留」「只保留两边都有的」…；新增 9 条 `hint*` 说明文字与校验语「还差一步：…」 |
| **布局** | 六步卡片全铺开、无步骤条；S1 无执行按钮（按钮在 S2 底部） | 顶部新增横向步骤条（图标 + 文字双编码）；S1 卡片底部补执行按钮，符合就近原则 |
| **无障碍** | 模态框无 `role=dialog`/Esc；图标按钮只有 `title`；大量裸 `focus:outline-none` | 补 combobox/dialog ARIA 与 Esc + 焦点归还；图标按钮补 `aria-label`；统一 `.focus-ring`；字号下限约束（正文 ≥14px、辅助 ≥12px） |

## 3. 关键修复项（对比度实测）

| 位置 | 整改前 | 整改后 |
| --- | --- | --- |
| 三处拖拽悬停高亮区 | `bg-primary-800` + 黑字，**3.13:1**（低于 AA） | `bg-primary-50` + `border-dashed border-primary-400` + `ring-2` |
| 删除 / 警示按钮 | `bg-red-500` 白字 3.76:1、`text-red-400` 图标 2.77:1 | 统一 `bg-red-50 text-red-600 hover:bg-red-100` |
| 占位符 | `text-black/50` 3.95:1 | 下限提到 `text-black/70`（README 硬约束定 `text-black/60` 为下限） |
| 项目名 / 修改时间 | `text-[10px]` / `text-[11px]` | 归零，统一 `text-xs`（12px）起 |

> 保留项：**主色按钮白字**（primary-800 白字 6.72:1，合规）。经用户确认「保留蓝底白字、改文档」，已把 README 硬约束补充为例外条款。

## 7. 出包结果

- 已执行 `npm run release`，版本递增 **3.6.1 → 3.6.2**。
- 产物：`release/新味智枢-v3.6.2-Setup.exe`（78 MB，NSIS x64）。
- 版本一致性实测三处均为 `3.6.2`：`package.json` · `dist/assets/index.js`（构建期注入的 `__APP_VERSION__`）· `app.asar` 内 `package.json`。
- 出包过程中修复了一个编码缺陷：`build-release.ps1` 原为 UTF-8 **无 BOM**，在 Windows 5.1 版 shell 下按系统 ANSI 解码导致中文乱码、脚本解析中断；已补 UTF-8 BOM。后续不要再用「另存为 ANSI / 无 BOM」覆盖该脚本。
