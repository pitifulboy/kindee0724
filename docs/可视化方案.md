# 步骤可视化 · 技术方案

> 目标：让用户**不看实际数据**，只通过表与表、字段与字段的关系，就能判断软件执行步骤配置是否正确。

## 0. 背景：为什么是两个界面

业务上「订单表 left join 辅助表」其实是**两步**：

```
界面1：【文件夹中的订单表】 ——合并（表头对齐）——> 【合并表】
界面2：【合并表】 ——LEFT JOIN——> 【辅助表1】、【辅助表2】…（1 个或多个）
```

所以拆成两个界面分别可视化，用户可逐步核对。

## 1. 界面1 · 待合并文件清单（简化版）

**只展示「拖入文件夹后其中的文件清单」，不展示字段、不展示数据、不展示合并结果。**

布局（单栏清单）：

```
┌──────────────────────────────┐
│ 待合并文件清单        3 个文件 │
├──────────────────────────────┤
│ 1. 采购订单明细1.xlsx         │
│ 2. 采购订单明细2.xlsx         │
│ 3. 采购订单明细3.xlsx         │
└──────────────────────────────┘
```

- 数据源：`orderFiles`（真实已选文件）
- 只列出文件名 + 数量 tag，不展示字段 / 数据 / 合并结果
- 空状态：未拖入文件时提示「尚未拖入待合并的订单文件夹」

**组件**：`FolderMergeView`

| prop | 类型 | 说明 |
|---|---|---|
| `orderFiles` | `{ id: string; name: string }[]` | 订单文件清单 |

## 2. 界面2 · 合并表 LEFT JOIN 辅助表（Power BI 风格）

参考 Power BI「模型视图」。

### 视觉规则

- 左侧一张「合并表」卡片；右侧纵向排列若干「辅助表」卡片。
- **匹配键**（`matchPairs` 里的字段）在两张表中**加粗 + 浅蓝底色块**高亮。
- 两张关联表之间用**曲线**连接，端点带小圆点，连接线用主色 `#1d4ed8`。
- 每张辅助表卡片标注连接方式（Left Join）。
- 未配置匹配键时，卡片内提示「未配置匹配键」。

### 交互规则

- **字段搜索（全局 + 卡内两层）**：
  - 右上角**全局搜索框**按名称（不区分大小写）过滤所有卡片展示的字段，仅显示匹配项并给出「匹配到 N 个字段」提示；清空（×）后恢复。
  - **每张卡片内各有一个「本表字段搜索」**（SVG `foreignObject` 内嵌输入框），只过滤该卡片自身的字段；因同一匹配键在不同表中可能叫法不同，卡内搜索**优先于**全局搜索，便于逐表定位。
  - 连线按过滤后的字段展示。
- **拖动卡片（Power BI 风格）**：按住卡片**表头**拖动即可移动该表在画布中的位置；位置限制在画布范围内，画布高度不随拖动变化（避免拖动时整体缩放抖动）。
- **连接方式（Left / Inner / Right Join）**：每张辅助表**表头右侧内嵌下拉**可选择该表的连接方式，与主页面「辅助表配置」中的同名选项共用同一 `how` 字段（`updateAuxTable`），两处修改互相同步。
- **卡内滑动字段**：未展开时每张卡片字段区最多显示 `MAX_VISIBLE_ROWS`（8）行，超出部分**滚轮在卡片内滑动**查看（`clipPath` 裁剪 + 右侧滚动条）；滚出视野的连线端点会**贴边并淡化**（虚线）提示字段不在当前视野。
- **全部展开字段**：顶部「全部展开字段」开关，一次展开所有卡片的全部字段（不裁剪、不滚动）。
- **每表底部展开/折叠按钮**：字段数超过 8 行的卡片，底部另有一条「展开全部 N 个字段 ▾ / 收起字段 ▴」，点击即可只展开/收起该表字段（独立于顶部全局开关）。
- **画布缩放按钮**：工具栏「－ / 百分比 / ＋ / 复位」调整整个建模画布的缩放比例（50%–200%，步进 25%），放大后画布容器可整体滚动查看。
- **关联字段上浮**：已建立关联的字段（匹配键）自动排到各表字段列表的**最上端**，便于对照查看匹配关系；搜索过滤后同样上浮。
- **编辑面板字段下拉复用 `SearchableSelect`**（软件内既有的可搜索下拉）：点击展开、面板顶部搜索框实时过滤、支持键盘选择。
- **拖拽字段连线建立关联（Power BI 风格）**：从任意字段行按住拖到另一侧表的字段行上松手，即建立一条关联。
  - 左 → 右：`orderCol = 拖出的合并表字段`，`auxCol = 落点的辅助表字段`
  - 右 → 左：`orderCol = 落点的合并表字段`，`auxCol = 拖出的辅助表字段`
  - 拖拽过程中显示虚线跟随光标；落在合法目标行时高亮为浅绿，线变绿；落在同侧 / 空白处不建立。
- **双击连线** → 弹出「修改关联关系」面板：
  - 左：合并表字段下拉（选项 = 合并表字段列表）
  - 右：辅助表字段下拉（选项 = 该辅助表字段列表）
  - 「取消」关闭；「确定」写回配置（`matchPairs`）
  - 「删除关联」：删除当前这条关联并关闭面板（由 `onRemoveMatchPair` 提供）
- 悬停连线加粗反馈。

### 布局算法（SVG 坐标）

```
CARD_W = 240      // 卡片宽
HDR_H  = 34       // 卡片表头高
ROW_H  = 26       // 字段行高
COL_GAP = 200     // 左右两列间距
V_GAP  = 20       // 辅助表卡片纵向间距
PAD    = 20       // 画布内边距
MAX_LEFT_ROWS = 8 // 合并表最多展示的字段行数
```

- `leftX = PAD`，`rightX = PAD + CARD_W + COL_GAP`
- 合并表字段 = 「所有被 matchPairs 引用的字段」优先全展示，再用其余字段补足到 `MAX_LEFT_ROWS`，多余显示为 `… 其余 N 个字段`
- 某字段行中心 Y = `cardY + HDR_H + rowIndex * ROW_H + ROW_H / 2`
- 连线：`M(leftX+CARD_W, leftY) C(mx, leftY) (mx, rightY) (rightX, rightY)`，其中 `mx` 取两列中点

### 组件 API

**组件**：`LeftJoinModelView`

| prop | 类型 | 说明 |
|---|---|---|
| `mergedColumns` | `string[]` | 合并表字段列表 |
| `auxTables` | `{ id; name; fileName; matchPairs; how }[]` | 辅助表配置 |
| `auxColumnsMap` | `Record<string, string[]>` | 辅助表 id → 字段列表 |
| `onChangeMatchPair` | `(auxId, pairIndex, field: 'orderCol'\|'auxCol', value) => void` | 写回匹配键（双击连线修改） |
| `onConnect` | `(auxId, orderCol, auxCol) => void` | 拖拽字段连线时新建一条关联（可选） |
| `onRemoveMatchPair` | `(auxId, pairIndex) => void` | 双击连线面板点「删除关联」时删除该条（可选） |

## 3. 页面布局 · CombinedPage 的六步流程（S1~S6）

「合并Excel + 金蝶导入」页按真实业务流水线重构为 **6 个步骤卡**（每卡一个 badge、一个可视化），并支持**每步独立执行**——仅在**渲染层**保存中间产物，后端调用 / 参数 / 预设**完全不变**（原 `VisualizationSection` 折叠容器已删除）。

```
S1 合并表格   → 界面1 · FolderMergeView（待合并文件清单）
S2 关联辅助表 → 界面2 · LeftJoinModelView（合并表 LEFT JOIN 辅助表） + 执行「S1·S2」
S3 订单拆分   → 界面3 · SplitOrderView                             + 执行「S3」
S4 模板匹配   → 界面4 · 复用 LeftJoinModelView（模板表 LEFT JOIN 明细表）+ 执行「S4」
S5 字段填充   → 日期 + 自定义填充规则 + 界面5 · 复用建模视图          + 执行「S5」
S6 汇总输出   → 输出目录 / 输出前缀                                 + 执行「S6」
```

执行入口与后端对应关系（**不新增 IPC**）：

| 步骤 | 执行按钮 | 后端调用 |
|---|---|---|
| S1+S2 | 执行「S1·S2」（`handleStep1Merge`） | `excelMerge.merge(...)`（一次完成合并 + 关联辅助表） |
| S3 | 执行「S3」（`handleS3Split`） | `kingdeeImport.step1` |
| S4 | 执行「S4」（`handleS4Match`） | `kingdeeImport.step2a` → `step2b` |
| S5 | 执行「S5」（`handleS5Fill`） | `kingdeeImport.step2c` → `step2d` |
| S6 | 执行「S6」（`handleS6Export`） | `kingdeeImport.step3` |

- 渲染层中间产物：`s3Result`（S3 拆分产物）、`s4Dir`（S4 step2b 输出目录，作 S5 输入）、`s5FilledFiles`（S5 step2d 填充文件，作 S6 输入）。统一由 `isExecuting`（六个执行态的逻辑或）互斥；重跑 S1·S2 时清空下游产物。
- S1 与 S2 因后端 `merge` 是一次调用，共用一个执行按钮（`btnExecS1S2`），S2 卡底部展示合并结果统计。
- 顶部保留「执行完整项目」一键跑完整流水线；执行进度 / 日志统一在顶部面板展示。
- **S4 中「模板表头所在行」紧跟在「模板表地址」输入框正下方**（布局微调）。
- 数据全部来自 `CombinedPage` 的现有 state，**不新增任何 IPC / 后端改动**。

### 自定义填充规则（S5，原「序号自增配置」）

该模块本质是**自定义填充**：把「一列要填什么」抽象成可增删、可拖拽排序的规则列表，字段映射的来源下拉直接引用规则名。后端 `seqConfigs` 结构与三种 `type` **完全不动**，仅调整前端呈现与文案：

- 标题「自定义填充规则」+ 说明文案；「+ 添加规则」按钮（`handleAddSeq`）。
- 规则类型下拉：`固定值`(constant) / `逐行递增`(sequential) / `按字段分组递增`(fieldBased)。
- `单号自增`（`id === 'seq-billNo'`）规则额外标注：它同时是 **S3 订单拆分**的单号生成依据（`startBillNo` / `billNoStep` / `billNoBaseField`）。

| 传入视图的 CombinedPage state | 用途 |
|---|---|
| `orderFiles` | 界面1 源文件清单（`FolderMergeView`） |
| `orderColumns` / `table1Columns` | 界面2 合并表字段（`LeftJoinModelView.mergedColumns`） |
| `auxTables` | 界面2 辅助表与匹配键（`LeftJoinModelView.auxTables`） |
| `auxColumnsMap` | 界面2 辅助表字段（`LeftJoinModelView.auxColumnsMap`） |
| `onConnect`（回调，非 state） | 拖拽连线时由 `CombinedPage.handleConnect` 向 `auxTables[auxId].matchPairs` 追加一条 |
| `onChangeJoinType`（回调，非 state） | 表头下拉切换连接方式时由 `CombinedPage.changeJoinType` 写回 `how` 字段 |

## 4. 界面3 / 界面4 · 客户订单拆分&匹配

> 视图现分别内嵌于六步布局的 **S3（订单拆分）** 与 **S4（模板匹配）** 步骤卡内（见 §3）；下述为视图规格。

```
客户订单表，拆分&匹配配置
├─ 配置区（订单表拆分依据 / 数据表匹配字段 / 模板匹配字段）
├─ 界面3 · SplitOrderView（订单拆分·第一步）
└─ 界面4 · 复用 LeftJoinModelView（模板匹配·第二步 · LEFT JOIN）
```

- **界面3 · 订单拆分**（`SplitOrderView.tsx`）：左「合并总表」（列出 `mergedColumns`，`groupByColumn` 加粗 + `#d9f2f9` 高亮）→ 中「按『X』分组 + 单号起始/递增」→ 右「订单文件」列表（`订单_{组}_{单号}.xlsx` 示例 + `订单拆分汇总.xlsx`）。
- **界面4 · 模板匹配 = 复用界面2 的 `LeftJoinModelView`**（第二步同属匹配逻辑，不另建组件）：左表 = 模板表（`templateColumns`，`matchFieldTable2` 高亮），右表 = 拆分明细表（`table1Columns`/`orderColumns`，`matchFieldTable1` 高亮），中间曲线 + Left Join 标注。通过 `leftTitle="模板表"` / `toolbarTitle="模板表 Left Join 拆分明细表（第二步）"` / `leftFieldLabel="模板表"` 定制文案；连接方式固定 `left`（不传 `onChangeJoinType`，下拉置灰）。拖拽连线 / 双击面板改键写回 `matchFieldTable2`（模板侧）与 `matchFieldTable1`（明细侧）。
- 业务依据：`service.ts` 的 `step1SplitOrders`（拆分）与 `step2a~2d`/`step3`（匹配、清理、填充、拆回、汇总）。
- 数据全部来自 `CombinedPage` 现有 state，**不新增 IPC / 后端改动**。

| 传入视图的 CombinedPage state | 用途 |
|---|---|
| `orderColumns` / `table1Columns` | 合并总表/明细表字段（`mergedColumns`，优先 `table1Columns`） |
| `groupByColumn` | 界面3 拆分依据（高亮 + 规则文案） |
| `startBillNo` / `billNoStep` | 界面3 单号起始与递增（取 `seq-billNo`） |
| `table2Path` | 界面4 模板表名 |
| `templateColumns` | 界面4 模板表字段 |
| `matchFieldTable2` / `matchFieldTable1` | 界面4 模板键 / 明细键（高亮） |

## 5. 界面5 · 字段映射复用建模视图（按运行口径：合并表列 / 自定义字段）

> 视图现内嵌于六步布局的 **S5（字段填充）** 步骤卡内（见 §3）；下述为视图规格。

```
S5 字段填充
├─ 自定义填充规则
├─ 字段映射（数据表取值）      ← 映射列表（模板列 / 数据表列）
├─ 字段映射（非数据表取值）    ← 映射列表（模板列 / 来源类型）—— 先配完所有取值
└─ 界面5 · 复用 LeftJoinModelView（模板表 ← 取值来源）
     左侧：模板表字段
     右列：合并表列卡片（运行时唯一数据源）
          + 「自定义字段」卡片（常量 / 日期 / 自定义填充规则）
```

- 左表 = 模板表（`templateColumns`）。
- 右列 = 按**运行口径**只分两张卡片（`mappingModel`）：
  - **「合并表列」**（`id: 'map-table1'`）：列出合并表全部列（`table1Columns`，未配置时回退 `orderColumns`）。辅助表在 S1/S2 已 LEFT JOIN **平铺进合并表**（列名冲突改名 `${列名}_${辅助表名}`），运行时模板表**只从这张合并表按列名取值**，故不再按来源辅助表拆分。
  - **「自定义字段」**（`id: 'map-custom'`）：列出 常量 / 日期 / 各自定义填充规则作为可选来源。
- 关联 = 每条 `sourceType === 'table1'` 的映射（模板列 ↔ 合并表列）落在「合并表列」卡；`sourceType !== 'table1'` 的映射落在「自定义字段」卡。
- 交互写回：合并表列卡拖拽连线 → 新增「数据表取值」映射；自定义字段卡拖拽连线 → 新增「自定义字段取值」映射；双击面板改键 / 删除 → 改 / 删对应映射（按 `auxId + pairIndex` 经 `pairIds` 定位 `id`；`map-custom` 的 auxCol 改键写回 `sourceType`）。
- 布局顺序：两个取值区（数据表 / 非数据表）位于**可视化之上**，便于「先配完所有取值再执行」。
- 文案：`leftTitle="模板表"`、`toolbarTitle="运行口径：模板表 ←（合并表列 / 自定义字段）"`、`auxHeaderBadge="字段映射"`（表头徽标替代「连接方式」下拉，避免误显 Left Join）。
- 视图目的：按**运行口径**呈现，帮助用户判断取值逻辑是否正确。此前按来源表拆分（合并表 / 辅助表1 …）属于展示启发式，会误导为"运行时从辅助表取值"，故已移除。
- **鲁棒性（避免"匹配关系不完整"）**：
  - 连线 React key 用映射 `id`（`pairIds` 与 `matchPairs` 平行），替代 `auxId-pairIndex`；
  - 「合并表列」卡在未读取合并表字段（未执行 S1·S2）时，**兜底并入已配置的 `table1Col`**，已配映射不丢线；同时在上方提示"请先执行 S1·S2"；
  - 自定义字段的**身份用 `sourceType`（唯一）**，展示用 `label`；`label` 重名时追加序号，避免 React key 冲突与 `find(label)` 误命中；旧预设里已废弃的来源类型（`materialCode`/`materialName`）也纳入列，避免丢线；
  - **未配置完整**（数据表取值缺模板列/数据表列；自定义取值缺模板列）的映射不在图上连线，但会在可视化上方以红色提示条数。
- 已知边界：同一模板列被多条映射命中时不拦截，`step2c` 按 mappings 顺序覆盖写同一列，结果取决于顺序。

| 传入视图的 CombinedPage state | 用途 |
|---|---|
| `templateColumns` | 左表模板表字段 |
| `table1Columns` / `orderColumns` | 合并表列（运行时数据源） |
| `fieldMappings`（`sourceType==='table1'`） | 关联（映射）来源 |
| `updateMappingPair` / `connectMapping` / `removeMappingPair`（回调） | 改 / 建 / 删映射 |

## 6. 约束

- 纯前端改动，**不触碰主进程 / IPC / 预设结构**。
- 文字颜色遵循项目硬约束：正文一律黑色；未匹配/错误提示用红色系。
- 不展示任何真实数据行，只展示「表 / 字段 / 关系」。
