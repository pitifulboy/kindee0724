## T6 打包发布 `[x]`

- **目标**：出 Windows NSIS 安装包。
- **前置**：
  1. 确认没有「新味智枢」进程在运行（否则 `app.asar` 被锁定）；
  2. 递增 `package.json` 的 patch 版本号。
- **命令**：`npm run build -- --publish never`
  - 直接 `npm run build` 时，若环境被识别为 CI，electron-builder 会在出包后尝试发布到 GitHub，缺 `GH_TOKEN` 报错；加 `--publish never` 可跳过。
  - 打包过程会访问 `%APPDATA%\electron-office`（Chromium 缓存目录），在受限沙箱下会被拦截，需在非沙箱环境执行。

## T12 界面5「数据表」按来源表拆分为多张卡片 `[x]`

- **目标**：界面5 右侧原来是一张「数据表」卡片，但该表的字段实际来自「合并表 + 各辅助表」的 LEFT JOIN 结果。按字段来源把这些字段拆分成多张来源卡片展示，而不是全塞进一张卡。
- **涉及文件**：
  - `CombinedPage.tsx`：新增 `mappingModel`（一次 `useMemo` 产出 `cards` 与每卡的 `pairIds`）；`mappingAuxTables` / `mappingAuxColumnsMap` 由 `mappingModel` 派生；`updateMappingPair` / `removeMappingPair` 从「按下标定位」改为「按 `auxId + pairIndex` 定位映射 id」。
- **来源判定规则**：`groupIdOf(col)` —— 命中 `orderColumns` → 「合并表」；命中 `auxColumnsMap[aux.id]`（含合并改名 `${列名}_${辅助表名}`）→ 对应辅助表；否则 → 「数据表」。卡片顺序：合并表 → 各辅助表 → 其他；无来源信息时退化为单张「数据表」。
- **验收**：见《可视化方案.md》§5；已通过 `tsc --noEmit`（0 错误）与浏览器自动化 12/12（「合并表」卡含采购单号/采购数量/采购日期、「产品信息」卡含物料编码/物料名称/单号，两卡表头均有「字段映射」徽标，4 条关联线，无单一「数据表」卡；界面2/4 回归正常）。
- ⚠️ **已被 T15 取代**：本任务的「按来源表拆多张卡片」口径属于**展示启发式**，会被误读为「运行时从辅助表取值」。T15 已改为按**运行口径**只分「合并表列 / 自定义字段」两张卡，`groupIdOf` 多卡逻辑已移除。
