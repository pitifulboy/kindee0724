# 界面设计评审报告 — 新味智枢

- 评审对象：Electron 桌面端「Excel 合并 → 金蝶导入」六步流水线界面（`src-electron/renderer/`）
- 评审维度：布局 / 文案 / 配色 / 无障碍（WCAG 2.2 AA）/ 微交互
- 评审方式：全量通读渲染层源码 + 对比度实测计算 + 桌面端窗口尺寸核算
- 本文只做评审与建议，**未改动任何逻辑代码**

---

## 1. 用户画像与设计目标

**目标用户：高中 ~ 大专学历的企业文员**（财务、采购、仓储录单岗），典型特征：

| 特征 | 对界面的含义 |
|---|---|
| Excel 熟练，但不懂编程概念 | 「列」「表格」「保存」能懂；「Join」「字段映射」「口径」不能懂 |
| 计算机操作会，但面对陌生软件不敢乱点 | 每步要有明确「我该点哪个按钮」的指引 |
| 可能 30~50 岁，视力一般 | 10~12px 小字是硬伤，正文至少 14px |
| 只做本职流程，不会探索 | 默认值要开箱可用；报错必须说「怎么改」而不是「哪里错」 |
| 一次处理大批文件，怕出错 | 破坏性操作要有确认，结果要能一眼确认「对了」 |

由此推导本项目应遵守的 5 条设计原则：

1. **一次只让用户面对一件事** —— 六步是流程，必须逐步引导，不能六步控件全铺开。
2. **用业务词，不用技术词** —— 「保留全部订单」而不是「Left Join」。
3. **执行按钮紧贴它作用的区域** —— 按钮在哪里作用，就在哪里出现。
4. **任何状态都要有文字说明** —— 不能只靠颜色/图标传达成功或失败。
5. **重要反馈必须够大、够清晰** —— 拖拽悬停、错误提示是最关键的时刻。

---

## 2. 总体判断

架构与工程规范（离线约束、Electron 安全基线、`appText` 集中文案、样式硬约束）是**扎实**的。问题不在「写得对不对」，而在于：

> **一套面向数据工程师的专家界面（Power BI 风格建模画布 + Join 术语 + 内部步骤编号），被直接暴露给了不懂技术的文员。**

三个最突出的结构性问题：

1. **认知过载**：单页纵向铺开 6 张配置卡，含 SVG 拖拽建模画布、字段映射表、填充规则卡片，一屏内几十个可交互控件 —— 用户不知道从哪开始。
2. **两套编号体系打架**：界面上是 `S1~S6 / 第 1~6 步`，执行日志里是 `步骤1 / 2a / 2b / 2c / 2d / 步骤3`。用户看到「2b」会彻底懵。
3. **最关键的拖拽反馈不可读**：拖拽悬停高亮区是**深蓝底 + 黑色文字**（对比度 3.13:1，不合规），恰好是用户最需要看清内容的那一刻。

## 3. 布局审查

### L1 · 六步全铺开，缺少流程感【P0】

`CombinedPage.tsx` 把 S1~S6 六张卡片（`border-2 border-blue-200`，视觉权重完全相同）从上到下全部渲染，无步骤条、无「当前进行到第几步」提示。完成状态仅靠执行后卡片内一行小灰勾 + 文字（如 `1152` 行的 `step1DoneLabel`）表示。

**影响**：文员打开就是一大片配置项，不知道起点与终点，容易中途放弃。
**建议**：顶部加一条**横向步骤条（Stepper）**，显示 `1 合并表格 → 2 关联辅助表 → 3 订单拆分 → 4 模板匹配 → 5 字段填充 → 6 汇总输出`，并区分「已完成 / 进行中 / 未开始」；一次只展开当前步，已完成步折叠为一行摘要，后续步置灰。这是让文员「知道自己在哪」的最低成本改造。

### L2 · 执行按钮与作用区域分离【P0】

S1「合并表格」卡片内**没有执行按钮**，只有一个文字提示「本步与第 2 步…执行按钮在第 2 步」（`appText.ts:166`），真正的按钮在 S2 卡片底部（`CombinedPage.tsx:1237-1262`）。

**影响**：违反「就近原则」。用户在第 1 步配置完订单文件后，找不到下一步该点哪里。
**建议**：S1 卡片底部放同款按钮（或把 S1、S2 合并为一张「准备数据」卡）。

### L3 · 双入口令人纠结【P1】

顶部 sticky 工具栏有「执行完整项目」一键按钮（`1045-1062`），每步卡底部又有各自的分步按钮（`执行 S1·S2`、`执行 S3`…）。

**影响**：文员不知道「我该点一键还是分步」，一键按钮还会跳过中间的配置校验提示。
**建议**：主推**一键执行**为主按钮，分步执行收进"高级/分步执行"折叠区；或首轮强制「逐步引导」，熟练后再开放一键。

### L4 · sticky 工具栏留白浪费【P2】

`1045` 行的粘性条 `p-4` 内只放了一个靠右按钮，左侧全空，且高度约 60px 常驻遮挡。

**建议**：与步骤条合并为一条「进度 + 主操作」工具栏，腾出纵向空间。

### L5 · 信息重复【P1】

项目名 + 修改时间出现 **3 次**：App 顶部标题栏（`App.tsx:227-233`）、CombinedPage 项目信息卡（`CombinedPage.tsx:1017-1040`）、右侧栏底部/选中态（`Sidebar.tsx:203-210`）。

**建议**：只保留 App 顶部一处；CombinedPage 的项目信息卡改为承载「本步骤配置状态摘要」才有价值。

### L6 · 侧栏在右侧，与阅读习惯相悖【P2】

`Sidebar.tsx:135` 用 `border-l` 挂在右侧，拖拽手柄在左边。中文用户从左到右阅读，项目列表作为「导航」放左侧更符合预期。
**建议**：若不影响既有约定，左侧放导航、右侧放内容；至少不要把唯一的项目入口默认藏在右侧。

### L7 · 宽屏空间未利用 【P2】

内容为单列 `max-w-5xl`（`CombinedPage.tsx:1006`），1200px 窗口下大量横向空间闲置；而配置项（`label w-32` + 控件）纵向堆叠，滚动很长。
**建议**：≥1280px 时把「文件类配置」与「参数类配置」拆成两列（CSS Grid `repeat(auto-fit, minmax(320px,1fr))`），减少滚动。

### L8 · 字段匹配行宽度不确定【P2】

`CombinedPage.tsx:1199-1215` 的匹配行是 `flex` + 两个 `SearchableSelect`（根元素 `w-full`，`SearchableSelect.tsx:127`），没有 `flex-1` 包裹元素，两个 100% 宽的子项会被 flex 压缩平分。

**建议**：给每个下拉包一层 `<div className="flex-1 min-w-0">`，宽度行为才可预期。

## 4. 文案与术语审查

`appText.ts` 已集中管理文案，但**术语密度与专业度**是面向文员的最大障碍。

### 4.1 术语对照表（建议直接替换）

| 现有文案（含位置） | 建议改为 | 理由 |
|---|---|---|
| `Left Join` / `Inner Join` / `Right Join`（`appText.ts:332-334`） | 保留全部订单 / 只保留两边都匹配的 / 保留辅助表全部 | 全英文技术术语，文员零认知 |
| `✓ 步骤2a: Join完成`（`:295`） | 关联辅助表完成 | 中英混杂 |
| `步骤2a / 2b / 2c / 2d / 步骤3`（`:290-307`） | 统一为「第 2 步 · 关联」「第 4 步 · 模板匹配」等 | 与界面 `S1~S6` 编号冲突 |
| `执行 S1·S2：合并 + 关联辅助表`（`:161`） | 第 1·2 步：合并表格并关联辅助表 | S1/S2 是内部代号 |
| `数据表匹配字段` / `数据表列` / `数据表取值`（`:232,243,337`） | 统一用「合并表」（合并结果表） | 同一个东西三个叫法，且与「合并表」并存 |
| `请选择模板表(Table2)`（`:280`） | 请选择金蝶模板表 | 暴露内部变量名 Table2 |
| `运行口径：模板表 ←（合并表列 / 自定义字段）`（`:256`） | 生成方式：把合并表的列填入模板表对应列 | 「口径」是行话 |
| `表头拖动卡片·切换连接方式 · 卡内滚轮滑动字段 · 底部展开/收起 · 拖拽字段连线 · 双击连线修改`（`:113`） | 拆成 3 条短提示，或改为按需显示的帮助气泡 | 11px 一整句，读不完 |
| `填充规则` / `序号自增` / `自定义填充规则`（`:221,286,285`） | 统一叫「自定义编号规则」 | 同一功能三个名字 |
| `逐行递增` / `按字段分组递增`（`:224,225`） | 每行自动加一 / 同一组用同一个编号 | 描述结果而非算法 |
| `单号起始值/递增值`（`:228,230`） | 首个单号 / 每个订单加多少 | 更贴近业务语言 |
| `检测到重复字段名称`（`:342`） | 有重名的列，请先改好再执行 | 给出行动 |
| `正在生成导入金蝶汇总表...`（`:308`） | 正在生成金蝶导入表… | 语序别嘴 |
| `完成_批量金蝶导入`（`:354`） | 金蝶导入数据 | 下划线 + 术语 |
| `上次修改：`（`:20`）vs `最后修改：`（`:245`） | 统一为「最后修改：」 | 同一含义两种写法 |
| `订单文件` / `辅助表` | 保留，但首次出现加一句人话说明 | 业务词可保留，需解释 |
| `字段` | 首次出现写「列（字段）」，之后统一用「列」 | 文员更熟悉 Excel 的「列」 |

### 4.2 说明文字缺失【P1】

- **辅助表是什么？** 全流程只出现「辅助表」三字，没有一句话解释「辅助表 = 需要一起匹配过来的补充信息表」。
- **模板表从哪来？** 没有说明「这是金蝶导出的导入模板」。
- **拆分依据怎么选？** 「订单表拆分依据」无示例（如「通常选『采购单号』」）。
- **默认值缺失**：`labelGroupByColumn`、`matchFieldTable1/2`、`fieldMappings` 等关键项默认为空，文员不知该填什么。

**建议**：在每个关键配置项下方加一行 12px 灰色说明（如「通常选『采购单号』」），并在首次进入时给一个「加载示例配置」按钮。

### 4.3 提示语气【P2】

校验提示偏「系统口吻」：`请选择分组列`、`请配置匹配字段`。建议统一为「还差一步：请选择拆分用的列」，并在界面上用**行内红色提示**而非仅 Toast（Toast 4 秒后消失，用户看不到）。

## 5. 配色审查

### 5.1 主色色阶本身是断裂的【P0】

`tailwind.config.js:10-21`：

| 级 | 50 | 100 | 200 | 300 | 400 | 500 | 600 | 700 | 800 | 900 |
|---|---|---|---|---|---|---|---|---|---|---|
| 色值 | #f0fafd | #d9f2f9 | #b3e6f3 | #80d6ea | #7dd0e6 | #60c7e0 | #3eaecb | **#2563eb** | **#1d4ed8** | #0e4d62 |
| 色相 | 青 | 青 | 青 | 青 | 青 | 青 | 青 | **蓝** | **蓝** | 深青 |

**600 是青色（#3eaecb），700 突然变成蓝色（#2563eb）** —— 这不是一条色阶，而是两条色阶拼接。后果：
- 按钮（primary-800 蓝）、高亮底（primary-100 青）、拖拽边框（primary-400 青）来自不同色系，整体「不统一」但说不出哪里怪。
- 无法按「primary-700 是 primary-600 加深一档」的直觉取色。

**建议二选一**：① 统一到蓝色系（把 50~600 换成蓝的浅阶）；② 统一到青色系（把 700/800 换成青的深阶）。**推荐 ①**（改动小、与现有大量蓝色按钮一致）。同时把色阶值与语义对齐。

### 5.2 对比度实测（WCAG 2.2 AA）【P0/P1】

实测计算（见文首诊断图）：

| 场景 | 位置 | 对比度 | 阈值 | 判定 |
|---|---|---|---|---|
| 黑色文字压深蓝底（拖拽悬停高亮区） | `CombinedPage.tsx:1124,1181,1381` 的 `activeClassName` | **3.13:1** | 4.5:1 | ❌ 不合规 |
| 占位符 `text-black/50` | `SearchableSelect.tsx:137` | **3.95:1** | 4.5:1 | ❌ 偏低 |
| 错误 Toast 红底白字 `bg-red-500` | `Toast.tsx:22` | **3.76:1** | 4.5:1 | ❌ 偏低 |
| 删除图标 `text-red-400` | `Sidebar.tsx:230` | **2.77:1** | 3:1 | ❌ 不合规 |
| 主色按钮白字 `bg-primary-800` | 全局 | 6.72:1 | 4.5:1 | ✅ |

**最严重的是第 1 行**：拖拽文件悬停时，容器背景变成深蓝 `bg-primary-800`，但里面 `label`（"订单文件:"）和文件名仍是 `text-black` —— **深蓝底黑字，几乎看不见**。这是拖拽交互中最重要的「我现在放手会放到哪里」的反馈时刻。

**修复建议**（保持蓝色主色不变）：
- 拖拽悬停区改为**浅色高亮**：`bg-primary-50 border-primary-400`，文字保持黑色 → 对比度 > 12:1。
- 或高亮区统一走「白底 + 蓝色虚线边框 + 左侧 4px 蓝色竖条」，既有反馈又不牺牲可读性。

### 5.3 语义色缺失【P1】

- **成功用蓝色**：合并结果面板（`CombinedPage.tsx:1266`）、成功 Toast（`Toast.tsx:22`）都用 `bg-primary-800`（蓝）。按语义成功应为绿色，否则用户无法从颜色区分「成功了」还是「普通信息」。项目自己的硬约束「错误红/成功绿」在此被违背。
- **建议**：成功 → `bg-green-700`（白字对比度 5.0:1）或 `bg-green-50 text-green-800` 浅底方案；错误 Toast → `bg-red-500` 改为 `#b91c1c`（白字 6.4:1）。
- **信息提示**：`bg-blue-50`（`1124` 等）与 `primary-*` 混用，建议统一。

### 5.4 建模画布配色过多【P2】

`LeftJoinModelView.tsx:87-91` 一处定义了 5 种强调色（KEY_FILL 青、HOVER_FILL 绿、LINE_COLOR 蓝、CONNECT_COLOR 绿、DIM_LINE 浅蓝）＋ 若干中性灰。颜色语义不统一，用户难以建立「哪种颜色代表什么」的心智。

**建议**：收敛为「1 个主色（关联线）+ 1 个语义色（拖拽目标=绿）+ 中性灰」，其余一律灰阶。

### 5.5 整体观感

配色偏「工具感、冷」，缺少一个明确的品牌色记忆点。建议：主色定一个（推荐蓝），成功/警告/错误各一，中性灰 4 级，**总共不超过 3 个彩色系**。

## 6. 无障碍审查（WCAG 2.2 AA）

| # | 问题 | 位置 | 影响 | 建议 |
|---|---|---|---|---|
| A1 | 大量 10~12px 小字 | `text-[10px]`/`text-[11px]`/`text-xs` 遍布（如 `Sidebar.tsx:148,209,249`、`LeftJoinModelView.tsx:684,800`） | 老花/视力一般用户阅读困难，正文低于 AA 建议的 16px | 正文 ≥14px，辅助文字 ≥12px，取消 10~11px |
| A2 | 图标按钮只有 `title` 无 `aria-label` | `Sidebar.tsx:149,218,228`；`CombinedPage.tsx:1212,1501` | 屏幕阅读器不读 `title`（不稳定），纯图标按钮无可访问名 | 加 `aria-label` |
| A3 | `label` 未与控件关联 | 全站大量 `<label className=...>` 无 `htmlFor`/`id`（如 `CombinedPage.tsx:1318,1401`） | 读屏软件无法把标签与输入框关联 | 加 `id` + `htmlFor`，或改 `<div>` 避免语义误导 |
| A4 | 下拉选择器缺少 combobox 语义 | `SearchableSelect.tsx:129-150` | 无 `aria-haspopup`/`aria-expanded`/`aria-activedescendant` | 补 ARIA（可参考 WAI-ARIA combobox 模式） |
| A5 | 模态框无对话框语义与焦点管理 | `DuplicateColumnsDialog.tsx:23`、`LeftJoinModelView.tsx:809` | 无 `role="dialog"`/`aria-modal`、无焦点陷阱、无 Esc 关闭（编辑面板）、关闭后焦点不归还 | 补 `role="dialog"` + `aria-modal="true"` + Esc + 焦点陷阱 |
| A6 | 移除 outline 未给替代焦点指示 | `focus:outline-none focus:border-primary-400`（`CombinedPage.tsx:1191,1395` 等） | 键盘用户看不出焦点在哪 | 统一 `focus-visible:ring-2 focus-visible:ring-primary-500 focus-visible:ring-offset-1` |
| A7 | 建模画布键盘不可达 | `LeftJoinModelView.tsx` 整体 SVG 拖拽 | 连线只能鼠标拖，无键盘替代 | 已有「匹配字段」表单行可作为替代，应明确为**主要**操作方式（见 L1 建议） |
| A8 | 仅用颜色传达状态 | 连线「实/虚」、拖拽目标绿、匹配键高亮 | 色觉障碍用户无法区分 | 已用「加粗+底色」双编码（好）；连线淡出建议再加形状差异 |
| A9 | 触控/点击目标偏小 | 缩放按钮 `w-6 h-6`（24px）、`✕` 按钮 `px-1.5 py-0.5`（`LeftJoinModelView.tsx:604`、`CombinedPage.tsx:1501`） | 24px 低于 AA 建议的 24×24 最小目标 | 提到 ≥28~32px |
| A10 | 空态仅一行灰字 | 空项目列表、无辅助表（`CombinedPage.tsx:1162`） | 单调且无引导 | 加图标 + 行动按钮（「去添加辅助表」） |

## 7. 微交互与状态

| # | 现状 | 建议 |

| M1 | 按钮只做 `hover:bg-*` 变色 | 增加 `hover:scale-[1.02]` + `active:scale-[0.98]`，时长 `200ms ease-out`，仅动画 `transform`（GPU 加速） |
